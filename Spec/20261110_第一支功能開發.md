# FreeCivicTW 第一階段功能需求

文件日期：2026-11-10。文件用途：產品需求、內容規劃、互動設計與功能驗收依據。

本文件承接 [網站架構](網站架構.md) 的 React + Next.js、SSG、GitHub Pages 與軟體分層規範。本階段先完成需求及初始靜態內容，不代表網站功能已實作。

## 1. 產品定位與開發初衷

### 1.1 一句話說明

**讓沒有公民知識基礎的人，也能從生活問題出發，看懂台灣民主如何運作、自己選的是誰，以及遇到訊息時如何查證。**

網站預設使用繁體中文，面向所有想認識台灣民主制度的讀者，包括學生、首次接觸選舉的人、不熟悉地方自治的人，以及希望重新建立公民知識的成年人。不要求登入、付費或先懂政治術語。

### 1.2 開發初衷文案

以下為依開發者需求整理、可用於「關於本站」的初稿，統一維護於 `Data/site.json`：

> 我希望做一個讓任何人都能看懂的公民網站。即使沒有學過公民，也能知道台灣的政府如何運作、選票選出了哪些人，以及這些人能做什麼、需要接受誰的監督。
>
> 我也希望大家面對新聞、短影音與社群訊息時，可以多停一下、多問一句、多找一份來源。理解民主與學會查證，可以從生活中的小問題開始。這是我開發這個網站的初衷，也希望它能幫助更多人。

公開聯絡信箱：**[amaochen0110@gmail.com](mailto:amaochen0110@gmail.com)**。用途為內容更正、功能建議及合作聯繫。不得自行補寫開發者姓名、經歷、政黨立場、資金來源或官方合作關係。

### 1.3 產品原則

- 先解釋「跟我有什麼關係」，再介紹機關與法規；先用白話，再提供正式名稱與來源。
- 事實、制度說明、虛構教學情境與價值討論分開標示。
- 重視自由、人權、法治、公民參與與權力制衡，對不同政黨、人物與主張採相同的查證標準。
- 用清楚證據幫助讀者自己判斷；不提供支持特定候選人或政黨的投票推薦。
- 不因讀者答錯而嘲諷、貼標籤或判定政治傾向。
- 互動是幫助理解的工具，所有核心知識也要有可讀取、可搜尋的文字版本。

## 2. 學習成果與使用者需求

使用者完成入門路徑後，應能用自己的話回答：

1. 選行政首長與選民意代表有什麼差別？
2. 總統、行政院、立法院及地方政府如何分工？
3. 我戶籍地通常有哪些民選職務？為什麼別的地方選票種類可能不同？
4. 民意代表可以監督預算，是否代表他可以直接指揮機關施工？
5. 一則訊息有哪些地方需要查證？證據不足時可以怎麼做？

| 使用者情境 | 需要解決的問題 | 第一階段對應功能 |
| --- | --- | --- |
| 我完全不懂公民 | 不知道先看哪裡，也看不懂名詞 | 首頁三入口、快速入門、名詞白話解釋 |
| 我分不清官員與民代 | 不知道誰做事、誰監督、誰由誰任命 | 角色卡、互動政府關係圖、生活情境 |
| 我想知道自己選什麼 | 不知道中央與地方各有哪些票 | 戶籍地查詢、選舉職務卡、規則說明 |
| 我看見很生氣的標題 | 不知道如何確認真假與脈絡 | 媒體識讀方法與六種互動練習 |
| 我發現內容可能錯誤 | 不知道依據、日期及回報方式 | 來源中心、查核日期、聯絡更正入口 |

## 3. 制度內容的校正基準

下列是內容製作與程式規則共同遵守的基準，不沿用原草稿中過度簡化的數量或上下隸屬關係。查核日期為 2026-11-10；來源的公布／更新日期須另外記錄，不能以查核日取代。

### 3.1 地方自治與行政區

- 以實務學習入口並列 **6 個直轄市、13 個縣、3 個市，共 22 縣市**；不把「6 個直轄市加 3 個市」說成全部地方政府，也不把縣放在這些市的下層。
- 「市」需區分直轄市、市（基隆市、新竹市、嘉義市，俗稱省轄市）與縣轄市（如頭份市）；同叫市長，不代表自治層級相同。
- 依本次查得內政部概況，縣下有 **198 個鄉、鎮、縣轄市：146 鄉、38 鎮、14 縣轄市**，另有 **6 個直轄市山地原住民區**。不採用「195 位、35 鎮、7 個山地鄉」的草稿數字。
- 一般區的區公所是市政府派出機關，區長依法任用；不能把每個區都當成有民選區長與區民代表會的自治團體。
- 直轄市山地原住民區具自治地位，設民選區長及區民代表會，需單獨建立規則。
- 村、里是基層編組，村里長由居民依法選舉；村里不是另有議會與獨立自治預算的地方自治團體。
- 入門圖不把省畫成現行民選自治政府；進階說明保留省在法制上的定位，不宣稱省級法制已被全部刪除。

數量與地方制度參考 [內政部：我國地方制度概況](https://www.moi.gov.tw/cp.aspx?n=674)；機關、任用與自治例外參考 [地方制度法](https://law.moj.gov.tw/LawClass/LawAll.aspx?pcode=A0040003) 第 3、14、58、59 條及第 83-2 條以下。行政區數量日後由資料集取得，不散落硬編碼於 UI。

### 3.2 中央、選舉與任命

- 總統、副總統聯名競選，是同一張票選一組；行政院是最高行政機關，不能把「中央」等同於總統一個人。
- 立委須介紹區域、平地／山地原住民，以及全國不分區及僑居國外國民三類；不分區以政黨票選出，不是另外直接圈選一位不分區候選人。
- 立法院法定席次為 113 席，包含區域 73 席、原住民 6 席、不分區及僑居國外國民 34 席。介紹政黨票時說明依法有分配門檻，不簡化成每個政黨只要有票就有席次。
- 一般規則下的立委候選人票為「區域或相應原住民立委」擇一類，不是先投區域再多領一張原住民立委票。
- 行政院長由總統任命；各部會首長等依憲法由行政院長提請總統任命。不是總統選完就能任意任命全部公務人員。
- 依法須經立法院同意的人事案件，例如總統提名大法官，圖上須標出提名、同意與任命程序；地方首長的人事權也須區分依法任免及專屬人事制度，不能畫成任意任用。

選舉與人事程序參考 [憲法增修條文](https://law.moj.gov.tw/LawClass/LawAll.aspx?pcode=A0000002) 第 2 至 6 條、[憲法](https://law.moj.gov.tw/LawClass/LawAll.aspx?pcode=A0000001) 第 53、56 條，以及 [行政院：選舉及公民投票](https://www.ey.gov.tw/state/62879155A536D543/c78552af-72f4-45ef-bb89-a044cf2f3f1c)。解釋憲法本文時必須一併考量現行增修條文。

### 3.3 職權、法律與預算

- 民意代表負責議案、預算審議及依法監督行政；行政機關負責施政與執行。民代協助反映需求，不等於可以直接命令機關發包或違法核准案件。
- 中央法律由立法院審議；地方自治法規需分清議會／代表會議決的自治條例，與行政機關依法訂定的自治規則，不都叫「地方法律」。
- 法律提案可包含行政院提出與立委依程序提案；圖解須分開提案、立法院審議、總統依法公布及法律施行，不把某一機關的提案當成已生效法律。
- 預算教學區分「行政機關編列 → 民意機關審議 → 行政機關執行 → 決算與審計監督」；立委的預算審議不能直接稱為審計部的專業審核工作。
- 中央與地方各有預算及依法分配的財源，包含稅課、統籌分配及補助等；不能把全部公款畫成單一路徑「中央撥縣市、縣市再撥鄉鎮市」。
- 教學中的工程與金額均標示為虛構，不以簡化模型宣稱現實案件的權責、合法性或財政分配結果。

職權參考 [憲法](https://law.moj.gov.tw/LawClass/LawAll.aspx?pcode=A0000001) 第 63、70、104、105 條、[地方制度法](https://law.moj.gov.tw/LawClass/LawAll.aspx?pcode=A0040003)；審計成果可連至 [審計部總決算審核報告](https://auditreport.audit.gov.tw/)，財源用語參考 [財政部統計背景說明](https://web02.mof.gov.tw/njswww/webMain.aspx?k=i5100)。第一階段不模擬現行財劃法分配公式或實際金額。

## 5. 首頁與學習內容

### FR-01 首頁

- 首屏用一句白話說明網站用途，不要求讀者先判斷自己懂不懂政治。
- 三個主要入口為「先花 5 分鐘認識民主」、「查我能選哪些職務」、「練習看懂一則訊息」。5 分鐘是體驗設計目標，不能宣稱完成所有課程只需 5 分鐘。
- 快速路徑以中央分工、地方差異、選票意義與查證步驟各一張摘要卡帶路，讀者可隨時往完整文章深入；`/learn/` 頁面先提供這四步摘要，再列出八篇完整主題。
- 提供「總統會直接幫我修路嗎？」、「議員跟市長差在哪？」等生活提問，連至對應解釋。
- 首頁下方放簡短開發初衷、最近內容更新日期、完整來源與聯絡入口；更新日期來自內容資料。

每篇文章至少包含：一句話結論、生活問題、3 至 5 個重點段落、名詞白話解釋、1 個例子、1 題理解檢查與解析、常見誤解、來源及查核日期、上一課／下一課與相關功能入口。可按主題調整長度，預估閱讀時間必須標成估計。

第一階段至少解釋「行政首長、民意代表、自治、質詢、預算、決算、審計、政黨票、任命、提名同意、事實、意見、證據、脈絡」。名詞首次出現可點開說明，並能用鍵盤與觸控操作。

文章不得只有標題、摘要或尚未填寫的段落。快速摘要與完整文章使用同一份資料，避免兩種說法互相矛盾。

## 6. 互動政府圖與角色教學

### FR-03 政府怎麼運作

採用可點擊的 HTML／SVG 角色圖，分成「中央」、「地方」、「任命與監督」、「法律與預算」四個視角。桌面可並排圖與說明，手機改為垂直角色卡及分步導覽，不要求縮放整張複雜大圖。

- 點選角色，顯示白話工作、產生方式、權力、限制、監督關係與生活例子。
- 切換一種關係時，突出相應箭頭，其他關係保留脈絡；每條線附「選舉」、「任命」、「提名／同意」、「依法監督」、「業務執行」等文字。
- 不把所有線畫成命令或上下級；民意機關與行政機關並列，司法機關不得畫成受首長個案指揮。
- 「人民投票 → 產生角色 → 依法行使職權 → 公開資訊與監督」可逐步播放、暫停、上一步、下一步及重新開始。
- 預算／法律流程先給正常的教學路徑，再註明尚有法定程序與例外，不把「通過」一律等同「明天立即施行」。
- 動畫關閉或 JavaScript 未執行時，仍有完整角色說明及文字流程。

### 6.1 角色卡共用規格

每張卡包含 `一句話工作`、`怎麼產生`、`主要能做什麼`、`不能直接決定什麼`、`誰監督／受何限制`、`任命或同意程序`、`生活例子`、`來源與日期`。欄位不適用時說明原因，不用空白暗示沒有權力限制。

| 角色 | 白話重點與必須避免的誤解 |
| --- | --- |
| 總統／副總統 | 聯名選出；國家元首與依法行使職權；不是所有日常行政與地方工程的直接執行者 |
| 行政院長與部會 | 行政團隊推動政策；交代任命程序及向立法院負責；不是每個職務都由人民直選 |
| 立法委員 | 在立法院處理法律、預算及監督；區域服務不是直接指揮地方政府 |
| 直轄市長／縣長／市長 | 分別綜理所屬地方行政，與議會形成行政及民意監督關係 |
| 直轄市議員／縣市議員 | 審議相應地方議案與預算、監督地方政府；不同於鄉鎮市民代表 |
| 鄉長／鎮長／縣轄市長 | 管理所屬公所及自治事務；實際設施與服務仍依權責分工 |
| 鄉鎮市民代表 | 監督相應公所並審議自治事項及預算；不是縣議員的下屬 |
| 一般區長 | 市長依法任用，管理派出區公所；沒有因為叫「區」就必有區民代表會 |
| 山地原住民區長／區民代表 | 自治區的民選角色，與一般區規則不同 |
| 村長／里長 | 基層公務、服務、反映及協調；不是議員，也不能自行通過公所預算 |

角色精確權限以第 3 節來源為依據，實作內容審閱時補足對應條文與例外，不以卡片摘要取代完整法制說明。

### 6.2 生活情境

至少提供「學校旁路口想改善安全」、「公園設施需要維護」、「看到一筆預算被刪減的新聞」三個虛構例子。引導使用者先辨認道路／設施權屬、承辦機關、預算層級，再理解可以如何反映或監督。

情境不能宣稱全台路燈、公園、水溝都必定由鄉鎮市公所負責；資訊不足時回答「先確認設施權屬與主管機關」，並連結官方查詢方式。第一階段不建立可自動判定所有現實案件權責的引擎。

## 7. 戶籍地與選舉職務查詢

### FR-04 我能選哪些職務

產品入口採白話提問「我能選哪些職務？」；結果以「依所選戶籍地整理的選舉職務類型」呈現。這是制度教學，不是官方投票通知或當次選舉的個人可領票認證。

### 7.1 輸入方式

1. 使用者選擇「戶籍縣市 → 鄉鎮市區」，也可輸入地名搜尋候選項目。
2. 支援「台／臺」及前後空白正規化；同名地區如中正區必須讓使用者確認完整縣市，不自動猜測。
3. 明示「以戶籍地為準；現居地可能不同」。不用 GPS、IP 或手機定位推斷戶籍。
4. 不要求身分證、姓名、生日或完整住址；第一階段不需輸入村里、鄰或門牌。
5. 提供「比較一般、平地原住民、山地原住民立委規則」的教學選項，也可選「先看制度差異」。這是情境選擇，不要求讀者揭露真實身分。
6. 若有未選、無結果、歧義、資料載入失敗或資料未查核等情況，顯示可恢復操作的提示，不悄悄退回其他地區的規則。

### 7.2 中央選舉區塊

中央與地方分開呈現，明示通常屬不同的定期選舉，不把它們全部相加成「這次一定領幾張」。

| 職務／票別 | 顯示規則 |
| --- | --- |
| 總統、副總統 | 一張票選一組，不拆成兩張 |
| 立委候選人票 | 一般情境顯示區域立委；相應原住民選舉情境改顯示平地或山地原住民立委，不同時加上區域立委 |
| 政黨票 | 說明選擇政黨名單、影響不分區及僑居國外國民立委席次，不是直接圈選單一不分區候選人 |

在一般符合資格、總統與立委同日選舉的教學情境下，呈現上述三類票；必須附上戶籍期間、年齡、身分及當次選務公告會影響實際資格的說明。僑居國外、遷籍、補選、罷免、公投及其他特殊情況，不由本工具直接判定。

資格與票別依 [公職人員選舉罷免法](https://law.moj.gov.tw/LawClass/LawAll.aspx?pcode=D0020010)、[總統副總統選舉罷免法](https://law.moj.gov.tw/LawClass/LawAll.aspx?pcode=D0020053) 及 [中選會](https://www.cec.gov.tw/) 公告維護；不是所有「投票」都適用相同資格規則。

### 7.3 地方選舉規則矩陣

以下為定期地方選舉的職務種類教學；數量不含公投、補選及其他另外公告的投票。議員、代表實際所屬選區與類別須依官方資料及身分規則確認。

| 戶籍地類型 | 地方職務類型 | 教學用種類數 |
| --- | --- | --- |
| 直轄市一般區，如臺北市大安區 | 直轄市長、直轄市議員、里長 | 3 |
| 市的一般區，如嘉義市東區 | 市長、市議員、里長 | 3 |
| 縣轄市，如苗栗縣頭份市 | 縣長、縣議員、縣轄市長、市民代表、里長 | 5 |
| 縣下的鎮，如苗栗縣竹南鎮 | 縣長、縣議員、鎮長、鎮民代表、里長 | 5 |
| 縣下的鄉，如苗栗縣三灣鄉 | 縣長、縣議員、鄉長、鄉民代表、村長 | 5 |
| 直轄市山地原住民區，如新北市烏來區 | 直轄市長、直轄市議員、自治區長、區民代表、里長 | 5 |

規則以 [內政部地方制度概況](https://www.moi.gov.tw/cp.aspx?n=674) 及 [地方制度法](https://law.moj.gov.tw/LawClass/LawAll.aspx?pcode=A0040003) 為基準。不能單看「鄉／區」字尾或個人原住民身分，就決定是否有自治區長票；也不能因切換原住民立委情境，就自行多加一張地方議員票。

### 7.4 頭份市必備示範

選擇「苗栗縣 → 頭份市」後，地方區塊依序提供：

1. **苗栗縣長**：負責縣級施政；與頭份市公所的自治職權不同。
2. **苗栗縣議員**：審議縣級議案與預算，監督苗栗縣政府。
3. **頭份市長**：領導頭份市公所，處理依法屬於公所的行政與自治事務。
4. **頭份市民代表**：審議市公所相關自治事項與預算，監督市公所。
5. **戶籍所在里長**：基層公務、反映與協調；未輸入里別時，不憑空指定里名。

各卡可展開第 6.1 節角色欄位；同時標示「縣級」與「鄉鎮市級」，避免把頭份市長誤認為直轄市長。

原草稿的苗栗縣議員第 5 選區編號、範圍及席次，不作為跨年度固定規則。第一階段只保證職務種類，不顯示未完成當屆核對的選區編號、候選人或現任者；後續加入時，須附相應屆次的選委會正式公告與生效期間。

### 7.5 覆蓋範圍與結果狀態

- 正式版需涵蓋全台 22 縣市的全部鄉鎮市區，包含澎湖、金門、連江及全部山地原住民區，不能只完成頭份範例便宣稱全台可查。
- 地區需使用官方代碼或可追溯的穩定 ID，保留父層、名稱、類型、自治例外及資料版本；不自行杜撰行政區代碼。
- 地方職務種類可以由縣市與鄉鎮市區判定；精確選區若涉及村里／鄰與身分類別，不以這兩層資料假裝精確。
- 未選身分情境時，中央區塊顯示不同立委票的條件分支，不預設讀者一定屬一般選民。
- 每張結果卡包含來源與查核時間，資料過期或未查核時明示，不用空白卡冒充查詢成功。
- 不儲存地區與身分情境的組合，不放入可分享網址、分析事件或第三方服務。使用者可以清除選擇。

## 8. 媒體識讀教學與練習

### FR-05 看懂一則訊息

先提供可帶走的查證步驟：「停一下 → 找原始來源 → 看日期與完整脈絡 → 分辨事實、意見與證據 → 找獨立資料交叉核對 → 證據不足就暫不下結論或轉傳」。這是本站教學整理，不宣稱某單一步驟即可保證真偽。

六題初始題庫維護於 `Data/media-literacy-scenarios.json`：

| 題型 | 要練習的判斷 |
| --- | --- |
| 標題與內文不一致 | 不只看標題，核對範圍、條件與例外 |
| 舊訊息重新流傳 | 區分發布日期、事件日期與現在是否適用 |
| 短影音斷章取義 | 尋找前後文及完整版本，不由片段推斷全部立場 |
| 圖表與數字呈現 | 看單位、分母、比較基期與座標軸；相對與絕對變化分開 |
| 多篇報導其實同源 | 重複轉載不是多份獨立證據，也不代表內容必然為假 |
| AI 圖像與證據不足 | 外觀逼真不證明事件發生；外觀異常也不直接證明偽造 |

每題包含情境、待判斷主張、可逐步展開的證據、問題、選項、解析與可遷移到生活的查證行動。虛構地名、數字、素材、引句都標示「虛構教學情境」，不冒用真實新聞版面或捏造查核組織結論。

互動順序為「讀情境 → 選擇下一步／判斷 → 看證據 → 回答或修正 → 看解析」。允許修改答案，未作答也能看解析，不用限時、羞辱文案或排行榜。完成後顯示學到的方法與可複習題目，不產生政治傾向分數。

「來源是官方」與「新聞很多人轉傳」都不能單獨當作真實保證；可靠來源也須檢查適用範圍與原始證據。練習不提供對任意真實新聞的自動真偽裁決。

內容設計參考 [教育部：數位時代媒體素養教育白皮書入口](https://depart.moe.edu.tw/ED2100/News.aspx?n=1353704343B62511&sms=2ADD120E8E2615E3)；題目及答案為本站自編教學材料，並非教育部或查核機構對真實案件的判定。

## 10. UI／UX 與互動動畫

### 10.1 視覺方向

採溫和、清楚的學習介面：淺色背景、深色正文、少量強調色、足夠留白及一致的卡片／按鈕。機關與角色同時以名稱、圖示及文字標籤區分，不只靠顏色，也不以政黨配色暗示角色立場。

優先設計手機閱讀：一頁一個主問題、結論先行、更多內容逐步展開；保留返回上一個主題、清除選擇與完整來源的固定位置。文章頁可有目錄，手機目錄改為可展開區塊，避免遮住正文。

### 10.2 互動規格

| 互動 | 行為 | 替代方式 |
| --- | --- | --- |
| 角色與關係圖 | 點選角色、突出關係線、右側／下方展開說明 | 同內容的文字列表與鍵盤選取 |
| 任命／預算流程 | 逐步顯示本步角色及前後關係 | 上一步／下一步、直接閱讀全部步驟 |
| 地區查詢 | 搜尋建議、分層選擇、結果卡展開 | 可操作的原生表單或等效鍵盤介面 |
| 識讀練習 | 逐步展開證據、顯示解析、可修正答案 | 直接展開全部素材及解析 |
| 理解檢查 | 選擇答案後提供原因及回讀連結 | 無限時、可跳過、可再次作答 |

- 短轉場以 150 至 250ms 為設計起點，教學流程由使用者控制，不連續自動播放。
- 簡單動畫採 CSS；複雜流程可評估 [Motion](https://motion.dev/docs/react-accessibility) 等主流套件，實作前仍需依架構文件檢查相容性、體積與安全。第一階段不為動畫引入大型 3D 引擎。
- 支援 `prefers-reduced-motion` 及清楚的減少動畫控制；關閉動畫後資訊、操作與順序仍完整。
- 不要求拖曳、懸停或快速點擊才能完成任務；所有重點均能用觸控與鍵盤取得。
- 操作後保留合理焦點，以狀態文字／適當的 live region 宣告結果；展開控制提供可存取名稱與狀態。
- 360px、768px、1024px、1440px 版面皆需驗證。正文可放大、卡片不截斷、長地名不溢出。
- 載入、空資料、錯誤、重試與成功狀態均需設計，不能只有正常畫面。

- 來源缺漏、規則衝突、未查核內容及錯誤圖片引用均阻擋相關內容發布，不默默輸出預設答案。

## 12. SEO／GEO、隱私與成效

沿用 [網站架構](網站架構.md) 的 metadata、canonical、sitemap、JSON-LD、GitHub Pages 子路徑與 GA4 規範。本需求再補充：

- 文章的結論、完整正文、來源與日期存在於靜態 HTML；不能只有前端動畫或抓資料後才看得到的文字。
- 每篇獨立主題有穩定網址與唯一標題，互動說明可連至對應章節；`Article` 等結構化資料只描述真實存在的內容。
- 機關與職務名稱前後一致，來源、條件與例外緊鄰重要說法，方便讀者與搜尋系統核對。
- 不為每次查詢組合製造大量重複可索引頁面，不把真實身分情境放入 URL。
- GA4 未同意前不載入；拒絕分析仍可使用全部功能，並提供撤回入口。
- 可觀察事件包括 `learning_path_start`、`lesson_complete`、`ballot_lookup_complete`、`role_card_open`、`media_exercise_complete`、`source_link_open`。
- 參數採白名單，只記必要的公開內容 ID、流程步驟或題目 ID；不記戶籍地、原住民身分情境、輸入原文、完整來源網址或個人聯絡內容。答題答案與個人分數預設不送 GA。
- 不要求讀者提供姓名、證件、戶籍證明或聯絡資料；查詢與作答預設僅留在當次操作記憶體。GA4 使用的技術資料另於隱私說明交代並依同意機制處理，不宣稱整站完全不處理任何識別資料。未來若保存進度，須提供清除方式並由 Service／Repository 實作。

成效先看「讀者是否理解」，再看流量。可用性驗證以至少 5 位自述沒有相關基礎的自願讀者測試，目標至少 4 位能在不受提示下找到戶籍地查詢、說明一組行政／民代差異、完成一題查證步驟。這是待驗證目標，不是已證實的學習成效。

## 14. 交付順序與完成定義

1. **內容與資料基礎**：依本文件完成文章、角色、選舉規則、官方地區名冊與來源查核；本次 JSON 作為起始資料。
2. **核心閱讀與查詢**：實作首頁、入門文章、政府角色及全台選舉職務查詢，先確認制度與結果正確。
3. **互動體驗**：加入角色關係、流程動畫、六題媒體識讀及完整錯誤／空白狀態，完成手機與可存取性檢查。
4. **上線驗收**：完成關於／來源／隱私、SEO／GEO、分析同意及 GA4，執行資料檢查、關鍵行為測試與靜態部署驗證。

第一階段完成的定義是：P0 頁面及內容可用、全台規則覆蓋完成、第 13 節案例通過，並記錄尚有限制。只有畫面、範例頭份資料、待補文章或無來源的制度卡片，不算完成。
